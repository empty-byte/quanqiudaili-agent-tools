# 代理连接

## 使用已有账号

先用 `sub_account_list` 确认现有账号、产品、网关、端口和协议。用户要连接串或多个会话时，使用已有账号拼接；不要调用购买、创建账号、修改凭据或直连开关，除非用户另外要求并经过确认。

按用户需要的客户端格式交付 host、port、username、password、protocol。无明确连接格式时可先给字段映射；不要假定所有客户端都支持同一种 URL。账号不存在或返回缺少必要字段时说明缺项，不编造密码或网关。

## 动态出口地区

产品 1/6 使用 `dynamic_country_list`，再按需要调用 `dynamic_state_list`、`dynamic_city_list` 获取支持的地区编码或名称。只按用户要求限定地区，不凭城市名猜国家。国家、州、城市参数的层级及连接串拼写以 Session 规范为准。

产品 11 的购买 `country` 是接入网关，不是出口国家；连接主机以列表返回的 `target` 等实际字段为准。不要把产品 1/6 的地区列表声称为产品 11 的实时库存，也不要为更改出口地区尝试修改购买网关。

## Session 的唯一规范

先读取 MCP 资源 `quanqiudaili://docs/dynamic-proxy-session`；客户端不能读取资源时，读取同技能附带的[Session 规范副本](generated/dynamic-proxy-session.md)。副本由项目规范自动生成，发布时保持一致；不要在本文件另维护一套参数语法。

根据规范选择每次轮换或粘性会话；多个独立会话使用不同 Session ID，不能把同一 Session ID 配到不同地区要求。会话参数只是连接用户名的一部分，不会在管理后台创建新的子账号。连接串可以生成，不代表已经连通，也不保证每个会话绝对获得不同出口 IP 或在掉线时仍保持原 IP。

只有用户要求实际连通测试时才发代理请求；这可能消耗购买流量。默认提供可审阅的连接配置，避免把明文密码写入 shell 历史或无关文件。测试报告区分代理认证、目标站返回、出口信息和网络超时，不能把目标站拒绝归因于账号欠费。
