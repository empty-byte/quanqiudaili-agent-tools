# 删除与退单

## 删除动态子账号

`sub_account_delete` 仅删除产品 1/6 的一个子账号；`sub_account_delete_batch` 使用同产品的英文逗号 ID 列表。删除不可恢复，也不等于退款或回收购买费用。

先用列表查证每个目标，展示产品、用户名或备注、ID、数量及断连影响。只处理用户明确选中的范围；“删除测试账号”不能靠未核对的模糊搜索结果直接批量执行。用户仅问能否删除时只解释，尚未授权实际操作。用户明确同意 MCP 本次预览后才能执行。

删除后可按 ID 查询核对；若响应或查询不确定，报告未知，不自动扩大范围或重做整批。产品 11 和静态 IP 不走动态删除工具。

## 静态退单

`order_refund_apply` 按一个购买订单申请，`order_product_buy_id` 为整数，`ids` 为字符串数组。通过子账号列表核对订单归属，不同订单分开申请。

受限于下单 1 天内、已支付、未开发票的购买订单；续费、赠送、带宽升级订单不适用，有后续续费/升级记录或已申请的账号不能重复申请。单次数量还受后端限制（通常最多 30 个）；不要把“删除账号”替换成退单，也不要承诺申请必定获批或全额退款。

## 产品 11 退单

`order_refund_dynamic_bandwidth` 只传首个新购 `order_product_buy_id` 与原因，不传 `ids` 或本地子账号 ID。列表中的 `can_apply_back`、`order_back` 可辅助核实，最终以后端校验为准。

仅限下单 1 天内、已支付、未开发票、无后续续费或升级记录的首购订单。退款按审核时未使用天数折算，已用不足一天按一天扣除。审核通过会删除并终止子账号，不可恢复；有续费或升级记录等不符合自助条件时，说明需要联系支持，不尝试改订单 ID 绕过。

两种退单都需先说明对象、原因、审核流程及通过后的影响，再经 MCP 确认。返回提交成功后只报告“退单申请已提交”；不要说已经到账、已审核通过或账号已经删除。请求超时先核对已有申请，禁止自动重复提交。
