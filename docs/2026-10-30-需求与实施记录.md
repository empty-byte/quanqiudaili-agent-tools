## 2. 架构与安装方案

```text
用户业务请求
    → 客户端加载 quanqiudaili Skill
    → 按场景读取 references，查询并核对目标
    → 当前客户端的 quanqiudaili MCP 工具
    → JSON Schema 校验、写操作确认、HTTP 编码
    → PHP externalapi 鉴权、计价和执行

install
    → 选择客户端与范围，读取 API Key
    → 全量预检查和配置冲突检查
    → 复制自包含运行包、安装同一份 Skill、合并各客户端配置
    → 客户端重新加载并按自身机制授权
```

实施前曾考虑 APM 和 `skills` CLI。首版最终采用本项目内置 Node 安装入口：复用固定版本 `add-mcp@2.6.0` 的客户端路径及配置转换，使用自己的预检查、备份、更新和回滚逻辑，直接安装随包发布的 Skill。这样安装不依赖另一套包管理器，也能确保 Skill、工具定义及运行时来自同一份版本。没有另行安装 APM，也没有把第三方 Skills CLI 支持的全部客户端宣称为本项目支持。

职责分工：

- `src/install-cli.ts`：交互选择、参数、凭据输入、结果提示。
- `src/install-config.ts`：客户端白名单、Skills 路径、MCP 格式转换和配置合并。
- `src/install.ts`：预检查、版本目录、文件复制、安装记录、备份及失败恢复。
- `scripts/build-runtime.ts`：把运行时及依赖打包；安装后的 MCP 启动不依赖源码目录、npx 缓存或 node_modules。
- `scripts/build-skills.ts`：同步 Session 规范的随包副本。

### 使用入口

首次使用本地版本时，先下载仓库并进入项目根目录，再安装依赖与运行安装入口：

```bash
git clone https://github.com/empty-byte/quanqiudaili-agent-tools.git
cd quanqiudaili-agent-tools
npm ci
node dist/src/index.js install
```

`npm ci` 会自动构建；已有源码时从该项目根目录执行即可。也可使用 `npx -y github:empty-byte/quanqiudaili-agent-tools install`，由 npx 自动下载、安装依赖和构建，无需再手动克隆或执行 `npm ci`。两种方式任选其一，远端版本须包含安装功能。

在本地源码目录还可以使用以下选项；这些是不同用途的命令示例，不需要全部依次执行：

```bash
node dist/src/index.js install --agents claude-code,cursor,codex,gemini-cli,opencode --scope user
node dist/src/index.js install --list
node dist/src/index.js install --agents codex --scope user --dry-run
```

交互安装输入 API Key 时隐藏输入；非交互安装使用 `QQDL_TOKEN` 或显式 `--token-stdin`。安装入口不接受明文 `--token` 命令行参数，不把凭据写入 Skill、安装记录或输出。凭据按客户端机制写入本机配置，通常是明文；配置及原文备份都应当保密，项目级安装不得提交这些文件。

`--readonly` 安装只读 MCP，`--replace` 显式替换同名服务或冲突技能文件，`--dry-run` 不写文件且不要求凭据。已有不同配置或手工改动默认阻止覆盖。重复执行 `install` 更新安装器管理的内容；`setup` 保留原来的“仅输出配置”语义。

安装运行包位于 `~/.quanqiudaili-agent-tools/versions/<内容摘要>/`，客户端使用当次 Node 的绝对路径和该版本的绝对入口。多客户端安装相同内容复用该目录，客户端仍各自启动 MCP 进程。更换 Node 安装位置后重新执行安装。现阶段保留历史运行目录，不自动清理、不提供卸载子命令；未删除旧 Skill 文件，新增版本不再提供的文件也不会擅自删除用户内容。

JSONC 合并保留其他节点及注释。TOML 合并保留设置值，但会重新排版、移除注释；覆盖前在原文件旁保存 `.qqdl-backup-<摘要>`。写入失败会尝试恢复本次已经改动的文件，恢复异常明确报错；备份和已创建空目录可能保留。

安装器不执行线上请求，不自动批准客户端工具权限，也不关闭 MCP 写确认。一次安装表示一次部署 Skills 与 MCP 文件；客户端信任、启用或重启仍遵循各客户端机制。本次实施没有执行发布；GitHub npx 命令只有下载到包含本次实现的版本后才支持 `install`，仓库更名不能证明远程已有这些文件。

## 3. Skill 的完整覆盖

入口：[skills/quanqiudaili/SKILL.md](../skills/quanqiudaili/SKILL.md)。工具归属：[tool-map.json](../skills/quanqiudaili/references/tool-map.json)。

| 流程 | 主要参考文件 | 独立归属工具数 | 重点 |
|---|---|---|---|
| 产品与购买。 | `products-and-purchase.md`。 | 13。 | 产品识别、余额、地区/IP 段、库存、阶梯价、四种购买工具。 |
| 账号与流量。 | `accounts-and-traffic.md`。 | 9。 | 分页与目标核对、创建账号、备注、账密、直连、用量与限流。 |
| 续费与带宽。 | `renew-and-bandwidth.md`。 | 9。 | 保留自动续费设置、分组续费、报价、带宽升级和监控。 |
| 删除与退单。 | `delete-and-refund.md`。 | 4。 | 单个/批量删除、两类退单、ID 区别、审核及不可恢复影响。 |
| 代理连接。 | `proxy-connections.md`。 | 3。 | 动态地区层级、查询连接信息、轮换/粘性会话、Session 资源。 |

38 个工具各有一个维护归属，跨流程仍可复用。Skill 不复制完整 JSON Schema，调用参数以 MCP 实际暴露的 schema 为准。

共同流程要求包括：

- 产品 11 的 Go ID、本地子账号 ID、首购订单 ID 分别处理，不能混用。
- 搜索零命中可能返回全量账号，逐条核对用户名/IP；分页不完整或目标不确定时不批量写入。
- 确认前展示实际对象、参数与费用或影响；查询、试算、生成连接串不能扩大成写操作。
- 用户拒绝或未回复就停止，不能仅等待确认码静默期结束后提交；静默期本身无法证明用户同意。
- 写请求超时或结果未知不自动重试；当前没有订单查询工具，必要时由用户在网站核实。
- 退单申请成功不等于退款完成，批量异步受理不等于全部修改成功。
- 缺失 MCP、只读模式或接口能力不足时说明限制，不直接请求后端绕过。

Session 规则以 `spec/dynamic-proxy-session.md` 为单一来源。优先读取 MCP 资源 `quanqiudaili://docs/dynamic-proxy-session`，不支持资源读取时使用 Skill 内生成副本。更换 `ss` 只改变代理会话，不创建新的业务子账号，也不能保证出口 IP 绝对不同或永不改变。
