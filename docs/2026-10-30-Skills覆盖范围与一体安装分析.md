# Skills 完整覆盖与跨 Agent 一体安装分析（历史方案）

> 状态：2026-10-30 实施前的方案比较。最终采用本项目内置安装器，本文不再提供拟议安装命令或未来待办。当前安装方式见 [使用指南](../USAGE.md)，完成范围与验证记录见 [需求与实施记录](2026-10-30-需求与实施记录.md)，文档分类见 [阅读入口](README.md)。

## 当时新增的要求

在 [Skills 功能设计](2026-10-30-Skills功能设计分析.md) 的基础上，用户要求 Skills 和 MCP 一次安装，并覆盖 Claude Code、Cursor、Codex 以外的 AI 编程 Agent。

“一次安装”指一个入口为所选客户端分别部署技能、配置 MCP，并复用本地运行包；各客户端仍分别启动 stdio 进程。API Key、客户端信任、启用和重新加载仍遵循各客户端机制，安装不等于批准后续业务写操作。

## 方案比较与最终选择

| 当时评估的机制 | 最终处理与原因 |
|---|---|
| 单独使用 `skills` CLI。 | 未作为本项目安装入口。它解决技能分发，不能单独视为 MCP 已注册；不把其完整客户端名单当成本项目支持名单。 |
| Microsoft APM 清单组合安装 Skills 与 MCP。 | 初稿曾建议优先验证；最终未采用，未生成或要求安装 `apm.yml`，也未用本项目实测 APM。已有 Node 入口能承载所需流程，无需再要求用户安装另一套包管理器。 |
| 复用 `add-mcp` 并编写安装入口。 | 已采用固定版本 `add-mcp@2.6.0` 的客户端路径和配置转换；本项目实现预检查、合并、备份、更新、回滚，并直接安装随包 Skill。 |
| 各客户端原生插件。 | 保留为可能的分发渠道，未实现 manifest、marketplace 或商店发布；安装到一个客户端不会自动注册到其他客户端。 |
| 从源码路径或 npx 缓存长期启动 MCP。 | 一体安装器复制独立运行包到稳定版本目录，避免依赖下载目录；原有手动 MCP 接入方式仍保留。 |

对应实现为 [安装 CLI](../src/install-cli.ts)、[客户端适配](../src/install-config.ts)、[安装事务](../src/install.ts) 和 [运行包构建](../scripts/build-runtime.ts)。目前支持 11 种客户端适配；完整清单、用户级/项目级差异及参数以使用指南和 `install --list` 为准。

## 覆盖设计如何落地

初稿提出的“38 个工具均有主要归属”已落实，但参考文件重新分为产品与购买、账号与流量、续费与带宽、删除与退单、代理连接五类，不再使用初稿的拟议文件名。可机器校验的归属在 [tool-map.json](../skills/quanqiudaili/references/tool-map.json)，不在本文重复维护工具表。

影响流程的前置修正也已完成：产品 11 新购/续费/升级报价、动态流量 1–5000 GB 与阶梯价、产品 6 固定 30 天、Session 资源副本，以及确认文案。普通时长续费仍无精确报价工具，MCP 仍无订单查询工具；不能据此自动重试未知订单或承诺未经试算的金额。

初稿中“只有 setup，没有 install”“Skill 尚未创建”“产品 11 无报价参数”“先安装 APM 再做薄封装”等表述只描述当时分析状态，现已失效。拟议命令、重复实施清单和未经实现的卸载方案已删除；当前安装器没有卸载子命令，也不自动清理历史运行包。

## 证据与验证边界

分析阶段只查阅源码与第三方官方资料，没有安装 APM、原生插件或用户客户端。随后实施阶段完成了临时目录安装验证、真实 stdio 到本地假 HTTP 后端验证和部分独立模型流程评估；具体执行次数与限制只在 [实施记录](2026-10-30-需求与实施记录.md) 维护。配置适配通过不等于所有真实 GUI 版本和操作系统已经验收。

仓库远程已更名，对外地址为 [quanqiudaili-agent-tools](https://github.com/empty-byte/quanqiudaili-agent-tools)。按用户后续决定，npm 包名、CLI 和 MCP 握手服务标识也统一为 `quanqiudaili-agent-tools`；客户端配置名、业务 Skill 名 `quanqiudaili` 及资源 URI 保持原值。本地源码完成、远程名称变化和发布可下载版本是不同状态，不能因更名推断新版本已经上线。
